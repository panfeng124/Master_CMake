# 第 11 课笔记：把诊断实现拆成静态库

## 声明库目标

~~~cmake
add_library(<name> [<type>] [EXCLUDE_FROM_ALL] <sources>)
~~~

- `<name>` 是必填的库目标名。
- 库类型包括静态库（`STATIC`）和动态库（`SHARED`）。接口库用 `add_library(<name> INTERFACE)` 声明。
- `EXCLUDE_FROM_ALL` 将目标排除在默认构建集合之外。显式构建它或构建依赖它的目标时，仍会构建它。
- `<sources>` 是源文件列表。

## 链接依赖

~~~cmake
target_link_libraries(<target> <PRIVATE|PUBLIC|INTERFACE> <item>...)
~~~

`<target>` 是当前目标。`<item>` 可以是其他 CMake 目标、系统库名、库文件的绝对路径或导入目标（Imported Target）。

链接 CMake 目标时，除了链接库，还要考虑依赖目标的使用要求（usage requirements）。

| 关键字 | 当前目标使用依赖 | 使用者继承该依赖的使用要求 |
| --- | --- | --- |
| PRIVATE | 是 | 否 |
| PUBLIC | 是 | 是 |
| INTERFACE | 否 | 是 |

本课中，只构建 lab_probe 也会自动构建它需要的 lab_core。给 lab_probe 设置的私有宏不会反向传给 lab_core。检查 LAB_VERBOSE 的代码在 diagnostics.cpp 里，所以要给编译它的 lab_core 设置宏。

## 加入子目录

~~~cmake
add_subdirectory(source_dir [binary_dir] [EXCLUDE_FROM_ALL])
~~~

| 参数 | 是否必填 | 含义 |
| --- | --- | --- |
| source_dir | 是 | 子目录的源码目录 |
| binary_dir | 否 | 子目录对应的构建目录 |
| EXCLUDE_FROM_ALL | 否 | 将该子目录排除在父目录的默认构建之外 |
