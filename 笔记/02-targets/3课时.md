# 第 13 课笔记：用三个目标验证 PUBLIC 与 PRIVATE 链接

依赖关系是 `lab_probe → lab_status → lab_core`。`add_library()` 声明静态库目标，`target_link_libraries()` 声明它的依赖和传播范围。

## 中间库怎样传递头文件搜索路径

核心库先通过 `PUBLIC` 提供头文件搜索路径。

```cmake
target_include_directories(lab_core PUBLIC include)
target_link_libraries(lab_status PRIVATE lab_core)
target_link_libraries(lab_probe PRIVATE lab_status)
```

- 中间一行用 `PRIVATE` 时，`lab_status` 可以使用 `lab_core` 的头文件搜索路径，`lab_probe` 接收不到这条路径。构建应用时，我遇到了报错 `无法打开包括文件: “lab/diagnostics.h”: No such file or directory`。
- 把中间一行改成 `target_link_libraries(lab_status PUBLIC lab_core)` 后，`lab_status` 会继续向 `lab_probe` 传递这条路径。应用构建成功并能运行。

## 核心库怎样提供头文件搜索路径

如果改为 `target_include_directories(lab_core PRIVATE include)`，这条路径只供 `lab_core` 自己编译时使用。`lab_status` 无论用 `PRIVATE` 还是 `PUBLIC` 链接 `lab_core`，都无法从这条依赖获取该路径，`lab_probe` 也一样。

## 打卡复查

在临时副本里，把核心库的搜索路径改为 `PRIVATE` 后，`status.cpp` 首先报 `C1083`，缺少 `lab/status.h`。本课的两个头文件共用 `app/include`，编译器先读到 `status.h` 的包含指令。

让应用只调用 `print_status()`，并让中间库私有链接核心库时，最终的 `link.exe` 命令里仍有 `lab_status.lib` 和 `lab_core.lib`。应用成功运行。
