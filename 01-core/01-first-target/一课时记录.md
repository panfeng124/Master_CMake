# 第 1 课笔记 · 从 main.cpp 到 lab_cli.exe

## 在 PowerShell 中准备环境

`Set-Location`（简写为 `cd`）切换到练习目录。`$clion` 保存 CLion 工具目录的路径，`$env:Path` 决定当前终端去哪里查找程序。把三个工具目录放在前面，并保留原有的搜索路径。

```powershell
Set-Location 'F:\PF\LAB\Master_CMake\01-core\01-first-target'
$clion = 'C:\Program Files\JetBrains\CLion 2025.3.2\bin'
$env:Path = "$clion\cmake\win\x64\bin;$clion\ninja\win\x64;$clion\mingw\bin;$env:Path"
```

我在哪个目录？实际调用的是哪套工具？分别用下面两条命令检查。

```powershell
Get-Location
Get-Command cmake, ninja, g++
```

## 配置项目并生成规则

```powershell
cmake -S . -B build -G Ninja
```

| 参数 | 英文助记 | 在这条命令中的作用 |
| --- | --- | --- |
| `-S .` | Source | 从当前目录读取顶层 `CMakeLists.txt`。 |
| `-B build` | Build | 把构建文件写入当前目录下的 `build` 子目录。目录不存在时，CMake 会创建它。 |
| `-G Ninja` | Generator | 选择 Ninja 生成器，写出 Ninja 能读的构建规则。 |

本次实际练习中的 `build` 和 `build_pf` 已配置为使用 Visual Studio 生成器。要在同一份源码上试上面的 Ninja 示例，把 `-B build` 换为 `-B build_ninja`，后续构建时也使用 `build_ninja`。

## 构建指定目标

```powershell
cmake --build build --target lab_cli
```

| 写法 | 怎么读 |
| --- | --- |
| `--build` | 进入构建模式，让 CMake 调用已配置的构建工具。 |
| `build` | 去哪里构建？填配置时传给 `-B` 的目录。 |
| `--target lab_cli` | 构建哪个目标？名字来自 `add_executable(lab_cli main.cpp)` 的第一个参数。 |

**改完文件后要重新生成规则吗？** 只改 `main.cpp` 的内容，直接构建即可，构建工具会重新编译并链接。如果使用 Ninja 时修改了 `CMakeLists.txt`，下次构建时 Ninja 通常会先调用 CMake 重新生成规则，再继续构建。

## 英文帮助速查

出处：本机 `cmake --help`。读 `Explicitly specify a source directory` 时，*specify* 是“指定”，*source directory* 是“源码目录”。

```text
-S <path-to-source>          = Explicitly specify a source directory.
-B <path-to-build>           = Explicitly specify a build directory.
-C <initial-cache>           = Pre-load a script to populate the cache.
-D <var>[:<type>]=<value>    = Create or update a cmake cache entry.
-U <globbing_expr>           = Remove matching entries from CMake cache.
-G <generator-name>          = Specify a build system generator.
-T <toolset-name>            = Specify toolset name if supported by generator.
-A <platform-name>           = Specify platform name if supported by generator.
```
